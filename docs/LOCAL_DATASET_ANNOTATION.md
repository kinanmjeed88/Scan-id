## 1. الخصوصية وحماية البيانات الحساسة

1. تبقى جميع صور المستمسكات في المجلد المحلي المتجاهل `/Mostmskat/`، وتبقى جميع مخرجات الجرد والوسوم والتقسيمات في المجلد المتجاهل `local-data/`.
2. يمنع `.gitignore` وفحص `tool/check_private_ci_checkout.py` و`sparse-checkout` في جميع workflows دخول أي ملف من `Mostmskat/` أو `local-data/` إلى Git أو GitHub Actions.
3. تعمل `tool/local_annotation_studio.html` بسياسة أمان محتوى صارمة (`connect-src 'none'`) تمنع المتصفح تقنياً من إجراء أي اتصال شبكي خارجي.
4. **حظر البيانات الشخصية النصية في المرحلة الأولى:** هذه المرحلة مخصصة حصراً لوسوم اكتشاف المستندات وحدودها وتصنيف نوعها (`DocumentKind`). يحظر مخطط `scan-id-local-annotations-v2` تخزين أسماء الأشخاص أو أرقام الهويات أو العناوين أو نصوص OCR أو مسارات/أسماء الملفات الأصلية، ويرفض المدقق الآلي أي ملف يتضمن هذه الحقول.

## 2. تشغيل الجرد المحلي واستوديو التوسيم

### أ) توليد الجرد المحلي وبذرة التوسيم (مرة واحدة قبل بدء الوسم)

من جذر المستودع، شغّل أداة الجرد المحلية لفحص الملفات وحساب بصمات `SHA-256` و`dHash64` واكتشاف النسخ المتشابهة وتوليد ملف بذرة غير موسوم:

```bash
python3 tool/inventory_local_mostmskat.py --input-dir Mostmskat
```

لا يوجد في البناء الحالي كاشف يولّد `ai_suggestions`؛ أداة الجرد تترك هذا الحقل فارغاً. يحتفظ المخطط بالحقل منفصلاً للتوافق مع السجلات السابقة، ولا يجوز ترقيته إلى `documents` أو دمجه مع أي حدّ بشري.

تُنشئ الأداة محلياً داخل `local-data/` (خارج Git):
- `local-data/mostmskat-local-inventory.json`: الجرد المحلي الكامل شاملاً المسارات النسبية وبصمات المحتوى.
- `local-data/mostmskat-unannotated-seed-v2.json`: ملف بذرة متوافق مع `scan-id-local-annotations-v2` بحالة `unannotated` جاهز للفتح في الاستوديو.
- `local-data/mostmskat-redacted-summary.json`: ملخص إحصائي منقح خالٍ تماماً من المسارات والبصمات والبيانات الشخصية.

### ب) تشغيل استوديو التوسيم على Android أو الحاسوب

فتح `tool/local_annotation_studio.html` مباشرةً (`file://`) ليس مسار التشغيل الموصى به: سياسات المتصفح على الهاتف تختلف، وWeb Crypto قد لا يتوفر على `file://` أو HTTP عادي، كما أن حفظ المسودات والتنزيل والاستيراد تعتمد على صلاحيات/سلوك المتصفح. لذلك شغّل الخادم المقيد على **الحاسوب الذي يحتفظ بالصور والنسخة الاحتياطية**؛ لا يحتاج الهاتف إلى Python أو بيئة تطوير.

```bash
python3 tool/serve_annotation_studio.py --host 0.0.0.0 --port 8080
```

هذا خادم قراءة فقط: يقدّم صفحة HTML واحدة، يرفض مسارات الملفات الأخرى (`404`) وطرق الرفع (`405`)، ولا يخدم `Mostmskat/` أو `local-data/`. الصفحة نفسها تحافظ على `connect-src 'none'` ولا تتصل بأي خدمة خارجية. عند عدم توفر Web Crypto على أصل HTTP خاص، يستخدم التطبيق تنفيذ SHA-256 محلياً احتياطياً؛ ولا يغادر بايت الصورة المتصفح.

#### الخيار الموصى به: USB و`adb reverse`

1. صِل الهاتف بالحاسوب عبر USB. فعّل USB debugging وثبّت `adb` على **الحاسوب فقط** (لا تثبّت بيئة تطوير على الهاتف).
2. شغّل الخادم بالأمر أعلاه، ثم في نافذة طرفية ثانية نفّذ:
   ```bash
   adb reverse tcp:8080 tcp:8080
   ```
3. افتح Chrome على Android وانتقل إلى `http://127.0.0.1:8080/`. باستخدام منفذ localhost المعكوس، يمكن للمتصفح استخدام ميزات الأصل الآمن المعتادة. تحقّق من بقاء الخادم والمنفذ المعكوس متاحين طوال الجلسة.

#### بديل: Wi-Fi محلي موثوق

1. صِل الهاتف والحاسوب **بنفس شبكة Wi-Fi الخاصة الموثوقة**، وشغّل الخادم على `0.0.0.0`.
2. افتح على الهاتف عنوان LAN الذي يطبعه الخادم، مثل `http://192.168.x.x:8080/`؛ اسمح بالوصول على جدار الحماية المحلي عند الحاجة.
3. هذا المسار يستخدم HTTP غير مشفّر على الشبكة المحلية؛ لا تستخدم شبكة عامة أو شبكة لا تثق بأجهزتها. عناوين LAN لا تُنشر ولا يلزم فتح منفذ على الإنترنت. التنفيذ الاحتياطي المحلي لـ SHA-256 يغطي غياب Web Crypto على HTTP.

#### فصل تدفقات العمل والخصوصية

- **الواجهة:** فقط ملف الاستوديو يرسله الحاسوب إلى الهاتف. ملفات الصور لا تُخدم عبر الخادم.
- **الوصول إلى الصور:** اضغط منتقي الصور في Chrome Android واختر الملفات عبر تطبيق «الملفات»/منتقي Android. يمنح المتصفح وصولاً للملفات التي تختارها؛ تُقرأ محلياً بواسطة `File.arrayBuffer()` و`createImageBitmap(..., {imageOrientation: 'from-image'})`. لم يُجر اختبار فعلي على هاتف Android في هذه المهمة؛ التوافق مع منتقي Android و`createImageBitmap` موضح ومغطى بمحاكاة/فحوص آلية، ويحتاج تجربة هاتفك للتأكيد النهائي.
- **المسودات:** الحفظ التلقائي في `localStorage` خاص بأصل المتصفح على الهاتف ورمز الموسِّم، ويبقى على الهاتف ولا يتزامن إلى الحاسوب؛ قد يمحوه تنظيف بيانات المتصفح، لذا لا تعتمد عليه وحده.
- **تصدير JSON:** ينشئ المتصفح ملفاً بواسطة Blob ورابط تنزيل محلي، ويضعه عادةً في مجلد Downloads على الهاتف. راجع سجل تنزيلات Chrome أو تطبيق «الملفات» للتحقق من وجوده، وانقله يدوياً إلى مجلد محلي خاص وآمن. لا ترفعه إلى GitHub أو خدمة سحابية.
- **الاستعادة:** اختر الصور الأصلية نفسها أولاً (لإعادة بناء صور الجلسة)، ثم اختر JSON عبر زر الاستئناف. يطابق الاستوديو `image_id` ببصمة SHA-256؛ اختيار صورة مختلفة أو تعديل بايتاتها لن يستعيد سجلها. يتيح ذلك متابعة الوسم من ملف JSON حتى عند اختلاف أصل المتصفح، دون الاعتماد على localStorage.

### ج) خطوات العمل داخل الاستوديو

1. أدخل رمز موسِّم غير شخصي (`R1` للمراجع الأول، `R2` للمراجع الثاني المستقل، `ADJ1` للمحكّم).
2. اختر الصور الثابتة من مجلد `Mostmskat/` واضغط **«تحميل الصور وفحص EXIF والتكرار»**.
3. اختيارياً: حمّل ملف `local-data/mostmskat-unannotated-seed-v2.json` أو ملفك السابق لاستئناف عملك.
4. **التكبير والتحريك:**
   - على الهاتف استخدم أزرار `+` و`−` و`100%` و`ملاءمة` (والتكبير بالعجلة متاح على الحاسوب). الأزرار كبيرة للمس.
   - فعّل **«وضع التحريك (Pan)»** ثم اسحب الصورة بإصبعك. ارجع إلى **«وضع الرسم/التعديل»** لإضافة النقاط.
5. **رسم الزوايا وتعديلها:**
   - المس الصورة لإضافة الزوايا بالترتيب، واسحب مقبض الزاوية المحددة لتعديلها؛ مساحة الالتقاط حول كل مقبض أوسع لتناسب الإصبع. استخدم أزرار النقاط إذا احتجت تحديد زاوية بعينها.
   - استخدم أزرار **«ترتيب TL→TR→BR→BL»**، و**«تدوير البداية ↻»**، و**«عكس الاتجاه ⇄»**، و**«تراجع»**، و**«حذف الزاوية المحددة»**، و**«مسح جميع نقاط المستند»**.
6. **حفظ التقدم والاستئناف:**
   - يحفظ الاستوديو المسودة تلقائياً في `localStorage` للمتصفح باسم رمز الموسِّم (إحداثيات وحالات غير حساسة فقط دون صور أو أسماء ملفات).
   - قبل إغلاق الجلسة، اضغط **«تصدير وسوم JSON (v2.0.0)»** واحفظ الملف تحت `local-data/review-R1.json`.

## 3. مخطط البيانات المرجعية ونظام الإحداثيات (`scan-id-local-annotations-v2`)

المخطط الرسمي موثق آلياً في [`tool/schemas/local_reference_dataset_v2.schema.json`](../tool/schemas/local_reference_dataset_v2.schema.json) برقم إصدار `schema_version = "2.0.0"`.

### حقول كل صورة (`samples[]`)
- `image_id`: بصمة SHA-256 سداسية عشرية (64 محرفاً) لبايتات ملف الصورة الخام.
- `internal_code`: معرّف تسلسلي داخلي غير دال (`IMG-01` .. `IMG-19`).
- `image_format` و`decode_status`: صيغة الصورة (`jpeg`/`png`/`webp`/`bmp`) وحالة فك الترميز (`ok`/`failed`).
- `raw_width_px`, `raw_height_px`, `exif_orientation`, `width_px`, `height_px`: أبعاد المخزن الخام، وقيمة وسم التوجيه EXIF (`274` في المدى `0..8`)، والأبعاد النهائية بعد تطبيق التوجيه.
- `perceptual_dhash64` و`near_duplicate_cluster_id`: بصمة إدراكية محلية من 64 بت ومجموعة التشابه لمنع تكرار العينات أو تسربها بين مجموعات التقسيم.
- `image_source`: `camera_photo` | `screenshot` | `collage` | `video_frame` | `flatbed_or_web_scan` | `synthetic_graphic` | `unknown`.
- `capture_group_id`: رمز الجلسة أو المصدر عندما يكون معروفاً بدليل موثوق خارج اسم الملف؛ يُترك فارغاً `""` إذا كان مجهولاً.
- `suitability_status`: `annotatable` | `needs_review` | `unclear` | `unreadable`.
- `annotation_status`: `unannotated` | `in_progress` | `annotated` | `second_review` | `excluded`.
- `exclusion_reason`: إلزامي عند `annotation_status == "excluded"` وفارغ في غيرها (`decode_failed`, `exact_or_near_duplicate`, `synthetic_or_promotional_mockup`, `pre_cropped_no_background`, `video_or_ui_recording`, `backup_container`, `unreadable_or_extreme_blur`, `boundary_unscorable`, `unresolved_annotator_dispute`).
- `image_quality_level` و`difficulty_reasons`: مستوى الجودة العام وأسباب الصعوبة (`occlusion`, `partial_truncation`, `glare`, `blur`, `severe_perspective`, `document_overlap`, `low_light`, `compression`, `laminated_outer_pouch`, `other`).
- `annotator_id` و`annotated_at`: رمز الموسِّم المحلي وتاريخ الوسم بصيغة ISO-8601.
- `second_review`: كائن يوثق حالة المراجعة الثانية (`not_started` | `agreed` | `disputed` | `resolved` | `excluded_after_dispute`)، ورمز المراجع الثاني وتاريخ المراجعة، ورمز المحكّم وتاريخ التحكيم ورمز قرار الحسم.
- `no_document`, `document_count`, `documents[]`: قائمة المستندات البشرية المعتمدة.
- `ai_suggestions[]`: قائمة اختيارية محفوظة للتوافق فقط؛ لا يولّدها التطبيق حالياً، وتبقى منفصلة تماماً عن `documents[]` والوسوم البشرية.

### نظام الإحداثيات والتعامل مع EXIF والتحجيم داخل الأداة

1. **تطبيق EXIF أولاً:** تُطبَّق تحويلة التوجيه القياسية لوسم EXIF `274` قبل العرض والقياس (`ImageOps.exif_transpose` في Python و`createImageBitmap(file, {imageOrientation: 'from-image'})` في المتصفح). لقيم التوجيه `{5, 6, 7, 8}` تصبح `(width_px, height_px) = (raw_height_px, raw_width_px)`، وللقيم `{0, 1, 2, 3, 4}` تبقى `(raw_width_px, raw_height_px)`.
2. **العلاقة بين إحداثيات العرض وإحداثيات الصورة الأصلية:** إذا عُرضت الصورة الموجّهة على لوحة رسم أبعادها $(W_c, H_c)$ بمعامل تكبير $z$ وإزاحة تحريك $(t_x, t_y)$، فإن نقرة المؤشر $(v_x, v_y)$ داخل إطار العارض تُحوَّل إلى إحداثيات مطبّعة $[0, 1]$ نسبةً إلى الصورة الأصلية الموجّهة وفق:
   $$x = \operatorname{clamp}_{[0,1]}\!\left(\frac{(v_x - t_x)/z}{W_c}\right), \qquad y = \operatorname{clamp}_{[0,1]}\!\left(\frac{(v_y - t_y)/z}{H_c}\right)$$
   حيث الأصل $(0, 0)$ في أعلى اليسار، ومحور $x$ يتجه يميناً، ومحور $y$ يتجه أسفل، وتكون إحداثيات البكسل على الصورة الأصلية الموجّهة $(X_{\text{orig}}, Y_{\text{orig}}) = (x \cdot \text{width\_px},\; y \cdot \text{height\_px})$.
3. تتوفر دوال التحويل العكسي المغلقة بين $(x, y)$ وإحداثيات المخزن الخام $(x_{\text{raw}}, y_{\text{raw}})$ لجميع حالات التوجيه `0..8` في `tool/validate_local_annotations.py` (`raw_to_oriented_normalized` و`oriented_to_raw_normalized`).

## 4. بروتوكول التوسيم البشري والتحقق المزدوج

1. **اختيار الزوايا الأربع وترتيبها (`boundary_status = "complete"`):**
   - عندما تظهر الزوايا الأربع الفيزيائية للمستند كاملة داخل الإطار دون حجب، حدّد الزوايا الأربع بالترتيب مع عقارب الساعة بدءاً من الزاوية العلوية اليسرى في العرض (`1:TL → 2:TR → 3:BR → 4:BL`).
   - للمستمسكات الموضوعة داخل غلاف تكييس بلاستيكي شفاف (مثل بطاقات السكن)، حدّد زوايا **الوثيقة الورقية/البلاستيكية الداخلية نفسها** لا الحافة الخارجية الفائضة للغلاف الشفاف، وفعّل مؤشر `laminated_outer_pouch`.
2. **متى يُعتبر المستند محجوباً أو مقطوعاً وكيفية الفصل بين المرئي والتخمين:**
   - **`occluded` (محجوبة):** عندما تغطي أصابع اليد أو مستند آخر أو جسم معتم زاوية أو جزءاً من الحافة داخل الإطار.
   - **`partial` (جزئية/مقطوعة):** عندما يمتد جزء من المستند خارج حدود إطار الصورة.
   - في كلتا الحالتين **يُحظر تخمين موقع الزاوية المخفية تحت اليد أو خارج الإطار**؛ ارسم مضلع الجزء المرئي فقط (`visible_polygon` من 3 إلى 12 رأساً مرتبة مع عقارب الساعة) واترك `corners = null` ما لم تكن الزوايا الأربع الحقيقية نفسها لا تزال مرئية بالكامل.
3. **التعامل مع المستندات المتداخلة والمتعددة:**
   - أضف كائن مستند مستقلاً لكل وثيقة مرئية في المشهد.
   - عند تداخل وثيقتين، فعّل `document_overlap` لكلتيهما؛ تحصل الوثيقة الأمامية الظاهرة بالكامل على `complete` بـ 4 زوايا، وتحصل الوثيقة الخلفية المغطاة جزئياً على `occluded` بمضلع يحيط بجزئها المرئي فقط.
4. **متى يُسجل النوع `unknown`:**
   - سجّل `unknown` كلما تعذر الجزم البصري المباشر بنوع المستند من محتوى الصورة وحدها (طمس شديد، إضاءة معتمة، دقة مصغّرة جداً، أو ظهور وجه خلفي/جزء صغير غير مميز). لا تستنتج النوع أبداً من اسم الملف أو نسبة الطول إلى العرض.
5. **متى تُستبعد الصورة من تقييم الحدود:**
   - ضع `annotation_status = "excluded"` مع سبب صريح عندما تكون الصورة: (أ) تالفة لا تُفك (`decode_failed`)، (ب) نسخة مكررة أو شبه مكررة لصورة أخرى في المجموعة (`exact_or_near_duplicate`)، (ج) تصميماً إعلانياً/ثلاثي الأبعاد غير ملتقط بكاميرا لمستند مادي (`synthetic_or_promotional_mockup`)، (د) مسحاً مقصوصاً مسبقاً لحافة الإطار بلا أي خلفية محيطة (`pre_cropped_no_background`)، أو (هـ) مطموسة بحيث يستحيل تمييز حدودها (`unreadable_or_extreme_blur` / `boundary_unscorable`).
   - إذا كانت الصورة صالحة كمشهد لكن مستنداً بعينه داخلها لا يمكن تحديد حدوده بثقة، ضع للمستند `boundary_status = "undeterminable"` (يُستبعد آلياً من مقاييس الحدود دون حذف بقية المستندات الصالحة في الصورة).
6. **عدم اعتماد القصوص السابقة أو مخرجات النموذج كحقيقة مرجعية:**
   - لا تُعتبر حقول `crop` أو `suggestedCrop` أو `cropDraft` الموجودة في نسخ `.scanid` الاحتياطية ولا مقترحات النموذج السابق وسوماً مرجعية مستقلة.
7. **المراجعة الثانية وحسم الخلافات:**
   - يوسم المراجع الأول (`R1`) والمراجع الثاني (`R2`) الصور بصورة عمياء مستقلة تماماً (مع إلزام المراجعة الثانية لجميع الحالات الصعبة أو المتعددة أو الجزئية وعينة من الحالات السهلة، ويفضل كامل المجموعة عندما تكون صغيرة).
   - شغّل المقارنة الآلية بعد تثبيت عتبة اتفاق IoU مسبقاً (مثال `0.90`):
     ```bash
     python3 tool/validate_local_annotations.py local-data/review-R1.json \
       --images-dir Mostmskat \
       --compare local-data/review-R2.json \
       --polygon-iou-review-threshold 0.90 \
       --write-disputes local-data/disputes-R1-R2.json
     ```
   - عند وجود أي خلاف يعيد المدقق رمز الخروج `2` ويولّد قائمة الخلافات في `local-data/disputes-R1-R2.json` دون اختيار أحد الوسمين تلقائياً ودون حساب متوسط المضلعات. يفتح المحكّم (`ADJ1`) الحالات المتنازع عليها في الاستوديو ويحسمها وفق البروتوكول (`second_review.status = "resolved"` مع `resolution_code`) أو يستبعد الحالة من المقياس الذي يتعذر حسم مرجعه بثقة (`excluded_after_dispute`).
