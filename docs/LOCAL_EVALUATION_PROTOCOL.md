# بروتوكول التوسيم والتقييم المحلي — Scan ID

**الحالة:** مواصفة جاهزة للتطبيق، وليست مجموعة بيانات أو نتيجة تقييم. حتى 2026-10-26 لا توجد في المستودع مجموعة مستقلة موسومة بالقدر الذي يسمح بإعلان دقة تصنيف أو حدود أو OCR. لا تُنشأ تسميات من أسماء الملفات أو المسارات أو أبعاد الصور أو مخرجات النموذج.

## 1. الحوكمة والخصوصية

1. لا تُضمّن إلا صوراً يملكها المشروع أو توجد موافقة موثقة على تقييمها محلياً. تُراجع تراخيص أي مجموعة عامة قبل التنزيل أو الاستخدام التجاري.
2. تبقى الصور والنصوص والمفاتيح التي تربط المعرّفات بالمصادر على جهاز تقييم محلي مصرح به. لا تُرفع إلى Git أو CI أو خدمة خارجية؛ ولا تُرفق تقارير التقييم بأسماء الملفات أو قيم OCR أو إحداثيات كل صورة.
3. يُنشأ لكل عينة معرّف غير دال محلياً. أداة الوسم الحالية تستخدم SHA-256 من بايتات الصورة لمطابقة مراجعتين؛ يبقى هذا المعرّف خاصاً ولا يحتوي على اسم/مسار. لا يظهر اسم الملف أو المسار أو بيانات EXIF للموسّمين. إذا استُخدم مصدر خارجي لاحقاً، يجب تطبيق ترميز/مفتاح محلي يحمي بصمات المصدر.
4. لا تُسجل قيم حقول المستند الشخصية إلا إذا كانت الموافقة تغطي النسخ النصي صراحةً. أداة التوسيم تُنزّل JSON محلياً غير مشفّر؛ احفظه على قرص/مجلد مشفّر، وامنع النسخ السحابي/المزامنة، واحذف النص الخام بعد التحقق وفق مدة احتفاظ معتمدة. لا تدخل القيم في السجلات أو مخرجات CI.

## 2. تجميد البيانات والتقسيم

1. قبل التوسيم أو تشغيل أي مرشح، تُزال التكرارات وتُجمع الصور بحسب **المشهد/جلسة الالتقاط والوثيقة المادية ومصدرها**. توضع كل اللقطات والقصاصات والتحويلات المشتقة من مجموعة واحدة في القسم نفسه.
2. تُنشأ أقسام مستقلة للتدريب والتطوير والاختبار المقفول. يكون الفصل على مستوى المصدر والجلسة والوثيقة، لا على مستوى الملف. يمنع ظهور أي مشتق للصورة نفسها عبر قسمين.
3. يُحفظ بيان التوزيع المحلي قبل فتح نتائج الاختبار، ويُسجل إصدار البيانات وسياسة التقسيم وبصمات الملفات محلياً. لا تُستخدم أسماء الملفات لتحديد الفئة أو لصنع التقسيم. أداة الوسم الحالية تستخدم SHA-256 لمحتوى الصورة كمعرّف ربط ثابت بين المراجعين؛ هذا المعرّف نفسه يبقى محلياً وسرياً ولا يدخل Git أو CI.
4. تُسجل تغطية ظروف الالتقاط والفئات الموجودة فعلاً. لا تُملأ الخانات الناقصة بصور مولدة أو بتكرار مشتقات العينة نفسها، ولا يُعلن نجاح لفئة ليس لها عدد مستقل كافٍ.
5. لا يُستخدم قسم الاختبار المقفول لتدريب الأوزان أو اختيار النموذج أو العتبات. أي تعديل بعد الاطلاع على نتائجه يتطلب اختباراً مقفولاً جديداً.

## 3. ورقة التوسيم البشري

يعمل موسّمان مستقلان، لا يريان اسم الملف أو المسار أو مخرجات النظام أو وسم الموسّم الآخر. تستخدم الفئات الموجودة فعلاً في `DocumentKind` فقط: `unifiedNationalId` و`residenceCard` و`passport` و`rationCard` و`other` و`unknown`. هذه أسماء مخطط التطبيق وليست ادعاءً بأن صورة بعينها تحمل إحدى الفئات.

لكل صورة، يسجل كل موسّم بصورة مستقلة:

- عدد الوثائق المرئية، بما فيها الوثائق الجزئية أو المتداخلة؛ لا يُخمَّن عدد وثائق مخفية.
- لكل منطقة مرئية: الفئة من القائمة أعلاه أو `unknown`، ورباعي الحدود في إحداثيات الصورة الأصلية إذا أمكن تعيين الحدود بصرياً.
- حالة مستقلة للاكتمال: كاملة، مقطوعة/محجوبة، غير واضحة، أو غير قابلة للتوسيم. عند غياب زاوية حقيقية لا تُختلق زاوية؛ تسجل الحالة غير القابلة للتوسيم وتستبعد من مقياس الزوايا مع إبقائها في عدّ حالات الفشل/المراجعة.
- صلاحية القص: يحفظ كامل المستند المستهدف، أو يقطع جزءاً منه، أو يدمج/يلتقط مستنداً آخر، أو لا يمكن الحكم. يُقاس هذا منفصلاً عن شكل الرباعي وعن قبول النموذج.
- سبب الالتباس أو صعوبة الصورة عند وجوده، من قائمة ثابتة قبل بدء التوسيم؛ وتُعامل القيم الغائبة على أنها غير معروفة لا سلبية.

يفصل محكّم ثالث الخلافات مع إبقاء التوسيمين الأصليين وسجل قرار التحكيم محلياً. تُذكر نسبة الاتفاق قبل التحكيم، ولا تتحول الملاحظات الأحادية أو قصاصات المستخدم ذات المصدر غير الموثق إلى حقيقة مرجعية. لا يطلع المحكّم على تنبؤ النموذج قبل تثبيت الوسم النهائي.

## 4. مقاييس مسارات النوع والحدود

### تصنيف النوع

تُنشر مصفوفة الالتباس، والدقة الإيجابية والاسترجاع وF1 لكل فئة، وMacro-F1، وعدد حالات `unknown`/الامتناع. يُعرض كل من **التغطية** (نسبة الحالات التي لم يمتنع فيها المصنف) و**مخاطر الأخطاء ضمن الحالات المقبولة**؛ لا يُسمح بأن يبدو المصنف جيداً بمجرد إرجاع `unknown` دائماً أو بدمج الفئات في متوسط واحد.

### كشف الحدود والقص

تُقاس منفصلةً: الوثائق الفائتة، المناطق الزائفة، أخطاء الدمج والتقسيم، خطأ الزوايا المطبّع بقطر الصورة، تداخل المناطق، صلاحية القص البشرية، والقبول الآلي الخاطئ الصامت ومعدل الإحالة للمراجعة. لا يستبدل أي متوسط مجمّع عدّ حالات القص المقطوع أو الدمج الخاطئ. يُعرض الكاشف والمتحقق ونتيجة المسار الكامل كلٌ على حدة.

### عدم اليقين الإحصائي

تُرفق فواصل ثقة 95% بالمقاييس الأساسية، مع إعادة أخذ العينات على مستوى المصدر/الجلسة لا الملفات المشتقة. يحدد حجم الاختبار قبل الاطلاع على النتائج بما يجعل فاصل الثقة قادراً على اختبار حد المخاطر المعتمد. مثال تخطيطي فقط: عند صفر إخفاقات في `n` وحدات مستقلة وفق افتراض ثنائي الحدين، الحد الأعلى الأحادي 95% للمعدل هو `1 - 0.05^(1/n)`؛ تُختار `n` بعد اعتماد حد المخاطر، ولا يُعامل الصفر في عينة صغيرة كدليل على انعدام الخطر.

## 5. مراجع OCR واحتساب CER/WER

لا يبدأ حساب CER أو WER حتى توجد مراجع نصية موثوقة ومصرح بها لكل عينة داخلة في القياس، بعد نسخ مستقل مزدوج وتحكيم. تُستخدم حقول مرساة محددة مسبقاً فقط، ويعمل المحرك محلياً دون شبكة. تبقى المراجع والتنبؤات الخام خارج Git وCI والتقرير العام.

قبل التشغيل، يُثبت إصدار التطبيع والتقطيع. الحد الأدنى المقترح للتقرير هو تطبيع Unicode إلى NFC وتوحيد نهايات الأسطر، مع إبقاء الحروف والأرقام وعلامات الترقيم والتشكيل كما هي في القياس الصارم؛ لا تُحذف علامات عربية ولا تُحوَّل أشكال الحروف أو الأرقام لتجميل الدرجة بعد رؤية النتائج. يحسب:

- `CER = مجموع مسافة التحرير على مستوى محارف Unicode / مجموع محارف المراجع`.
- `WER = مجموع مسافة التحرير على مستوى الكلمات المفصولة بالمسافات / مجموع كلمات المراجع`.

يُذكر التعريف صراحةً، ويعرض القياس لكل لغة/نوع حقل مع فاصل الثقة. إذا كانت كل المراجع فارغة فالمقياس `N/A`؛ وإذا كان مرجع عينة فارغاً وتنبؤها غير فارغ، تسجل كهلوسة نصية ولا تُسقط بصمت من التقرير. تُحفظ الأرقام التجميعية فقط.

## 6. معايير القبول قبل أي اعتماد

لا توجد في هذه المواصفة أرقام عتبات أداء مختلقة أو معتمدة. قبل فتح الاختبار المقفول، يوافق مالك المنتج/المخاطر على حدود رقمية مسبقة لكل فئة وعلى أقل تغطية مسموحة، وحد أعلى للقبول الخاطئ الصامت، وحد أدنى لاسترجاع الوثائق، وحدود CER/WER عند إضافة OCR. **غياب هذه الحدود يعني أن نتيجة الاختبار غير قابلة للقبول، لا أن النموذج نجح.**

يكون قرار القبول ممكناً فقط إذا تحققت جميع النقاط التالية:

1. مصدر البيانات وترخيصها/الموافقة عليها والتقسيم المستقل موثقة، ولا يوجد تسرب بين التدريب والتطوير والاختبار.
2. جميع تسميات الاختبار مزدوجة ومحكّمة؛ وتُعلن حالات الغموض وغير القابلة للتوسيم والاتفاق بين الموسّمين.
3. تتحقق الحدود المسجلة مسبقاً على الاختبار المقفول لكل فئة، بفواصل الثقة لا بالنقطة المقدرة وحدها؛ ويكون فاصل القبول الخاطئ الصامت دون الحد الأعلى المعتمد، وفاصل الاسترجاع فوق الحد الأدنى المعتمد. لا يُقبل قص يقطع مستنداً أو يدمج مستندين لمجرد تحسن متوسط IoU.
4. يفي المصنف بحدود كل فئة وبحد التغطية/الامتناع، ويظل `unknown` متاحاً للحالات الملتبسة.
5. إن كان OCR ضمن النطاق، تكون المراجع مكتملة ومراجعة، وتفي نتائج العربية واللاتينية كلٌ على حدة بالحدود المعتمدة، مع قياس الموارد محلياً على الأجهزة المستهدفة.
6. يجري تشغيل المرشح وخط الأساس على عينات الاختبار نفسها وبإعدادات مجمدة؛ تُنشر النتائج التجميعية فقط، ولا تُضبط العتبات على الاختبار.

## 7. التدريب وضبط العتبات

لا يُدرّب نموذج ولا تُغيّر الأوزان أو العتبات إلا بعد إثبات فجوة محددة على بيانات التطوير، ووجود مجموعة تدريب مرخصة منفصلة ومراجعة، وتقسيم مستقل، وخطة مقارنة مسجلة مسبقاً. تُستخدم مجموعة التطوير وحدها لاختيار المرشح والعتبات؛ يظل الاختبار النهائي مقفولاً حتى التقييم الواحد بعد تجميد كل شيء. تحفظ الأوزان/التهيئات وبصماتها ونتائج المقارنة محلياً، ولا تُرسل الصور أو النصوص إلى CI أو خدمات خارجية.

**الحالة الحالية:** لا توجد تسميات مستقلة أو مراجع OCR متاحة، ولا حدود قبول رقمية معتمدة. لذلك لا يمكن إعلان دقة أو قبول نموذج أو حساب CER/WER في هذه الجولة؛ هذا الملف يحدد ما يلزم قبل فتح تلك البوابة فقط.
