# بروتوكول التقييم المرجعي المحلي ومنع تسرب البيانات — Scan-id

**الحالة (2026-10-26):** البروتوكول والأدوات المحلية لمخطط `scan-id-local-annotations-v2` و`scan-id-local-splits-v2` معتمدة ومفحوصة آلياً. التقسيم المستقل (`train / validation / test`) **مرفوض حالياً عن قصد** لأن مجموعة `/Mostmskat/` الحالية (21 ملفاً: 19 صورة ثابتة منها 11 صورة كاميرا لمستندات مادية فقط، دون بيانات جلسة التقطت بها ودون وسوم بشرية مكتملة) لا تستوفي شروط الاستقلال الإحصائي ولا تغطية الفئات (`rationCard = 0`، صور الخلفية السالبة `= 0`).

---

## 1. النطاق الصارم للمرحلة الأولى (Gap 1 فقط)

1. يغطي هذا البروتوكول حصراً بناء مجموعة مرجعية موثوقة موسومة بشرياً لاختبار:
   - اكتشاف وجود المستند وعدده في المشهد،
   - تحديد حدود المستند وزواياه الأربع (`CropGeometry` / `visible_polygon`)،
   - تصنيف نوع المستند (`DocumentKind`).
2. **خارج النطاق في هذه المرحلة:** دمج محركات OCR، أو تدريب النماذج، أو تعديل أوزان `ScanIdDocNet-v1` أو عتبات القرار المجمدة المحمية بواسطة `tool/verify_frozen_artifacts.py`.

---

## 2. حوكمة الخصوصية والملفات المرجعية

1. تبقى جميع صور المستمسكات في `/Mostmskat/` وجميع ملفات الجرد والوسوم والتقسيمات المحلية في `local-data/` خارج Git وGitHub Actions.
2. لا تحتوي ملفات `scan-id-local-annotations-v2` على أي بيانات شخصية نصية أو أسماء ملفات أو مسارات محلية؛ تُعرَّف الصور حصراً ببصمة `SHA-256` لبايتات الملف الخام (`image_id`) ومعرّف داخلي تسلسلي (`IMG-01`..`IMG-NN`).
3. لا يجوز استخدام ملفات النسخ الاحتياطي `.scanid` أو حقول `crop` / `suggestedCrop` / `cropDraft` أو مخرجات النموذج الحالي كحقيقة مرجعية، وتُفصل أي مقترحات آلية مساعدة داخل `ai_suggestions` دون ترقيتها إلى `documents` إلا بمراجعة بشرية صريحة.

---

## 3. منع تسرب البيانات وشروط جواز التقسيم (`train / validation / test`)

تطبق أداة `tool/create_local_evaluation_splits.py` خمس بوابات إلزامية قبل السماح بإنشاء ملف تقسيم:

1. **اكتمال الوسوم والتحكيم:** يجب أن يمر ملف الوسوم عبر `validate_local_annotations.py --require-complete` بتوقيع محكّم بشري (`ADJ*`) وبصفر خلافات مفتوحة (`open_dispute == 0`).
2. **معرّف جلسة موثق غير صوري:** يجب أن تحمل كل صورة غير مستبعدة معرّف جلسة حقيقي (`capture_group_id`) يجمع الصور الملتقطة لنفس الوثيقة المادية أو في نفس الجلسة أو من نفس الشخص/المصدر، وتُرفض المعرّفات المجهولة أو الصورية (`unknown`, `ungrouped`, `todo`).
3. **منع التداخل على ثلاثة مستويات:**
   - عدم اشتراك أي مجموعتين (`train`, `validation`, `test`) في `capture_group_id`.
   - عدم اشتراك أي مجموعتين في عنقود تشابه `near_duplicate_cluster_id`.
   - فحص المسافة الإدراكية الثنائية `perceptual_dhash64` عبر جميع أزواج الصور المنتمية لمجموعات تقسيم مختلفة، ورفض التقسيم فوراً إذا وُجد زوج بمسافة هامينغ `<= 10` بتات من أصل 64 (يكشف الصور المعاد تحجيمها أو المأخوذة كلقطات شاشة لصورة أخرى).
4. **استبعاد حاويات الفيديو والنسخ الاحتياطية:** لا تُستخرج إطارات فيديو لتوزيعها عبر مجموعات مختلفة؛ وأي ملف `.mp4` يسجل واجهة التطبيق أو ملف `.scanid` يكرر أصول الصور يُستبعد من العد المستقل.
5. **الحد الأدنى الإحصائي لمجموعة الاختبار وقفلها:**
   - ترفض الأداة افتراضياً أي تقسيم تقل مجموعة `test` فيه عن `3` جلسات التقاط مستقلة أو `12` مستنداً قابلاً لقياس الحدود (`--min-test-groups 3 --min-test-scorable-docs 12`)، ولا يُفرض تقسيم رقمي صوري (`70/15/15`) على عينة صغيرة يعطي مجموعة اختبار بلا قيمة إحصائية.
   - عند نجاح التقسيم، يُقفل بيان مجموعة الاختبار محلياً داخل `local-data/` مع بصمة `locked_test_set_sha256` وعَلَم `threshold_tuning_on_test_forbidden = true`. يُحظر ضبط العتبات أو اختيار المعاملات على مجموعة `test` المغلقة.

## 4. مقاييس التقييم المعتمدة وحدود الثقة الإحصائية

عند توفر مجموعة مرجعية مكتملة ومعتمدة بشرياً، تُحسب المقاييس التجميعية المنقحة فقط (دون كشف نتائج فردية لصورة بعينها في التقارير العامة):

1. **اكتشاف المستند وعدده:** دقة الصورة الخالية من المستندات (`no_document`)، ومعدل التطابق التام لعدد المستندات في المشهد المتعدد (`document_count`).
2. **تحديد الحدود والزوايا الأربع (على العينات ذات `boundary_status == "complete"` غير المستبعدة فقط):**
   - متوسط ووسيط والـ مئين العاشر لـ `Polygon IoU` في نظام الإحداثيات الموجّه المطبّع `[0, 1]`.
   - خطأ الزوايا الأربع المطبّع وبالبكسل على الصورة الأصلية الموجّهة (`TL, TR, BR, BL`).
   - معدل قبول قص خاطئ على حالات البتر أو الحجب (`partial` / `occluded`) التي يجب أن تطلب مراجعة يدوية بدلاً من قص مستند ناقص بصمت.
   - تُفصل الحالات ذات `boundary_status == "undeterminable"` والصور ذات `annotation_status == "excluded"` خارج مقام مقاييس دقة الزوايا مع الإبلاغ الصريح عن عددها وأسباب استبعادها.
3. **تصنيف نوع المستند (`DocumentKind`):** مصفوفة الالتباس التجميعية عبر الأنواع المعتمدة بشرياً، مع فصل الحالات الموسومة `unknown` لعدم إمكانية التحقق البصري عن أخطاء التصنيف الفعلي.
4. **الحد الأعلى الإحصائي لمعدل الفشل:** حتى عند تحقيق `0` أخطاء على $n$ جلسة التقاط مستقلة، فإن الحد الأعلى لمعدل الفشل عند مستوى ثقة 95% هو $p_{\max} = 1 - 0.05^{1/n}$ (مثلاً: $n=11 \Rightarrow 23.8\%$، $n=30 \Rightarrow 9.5\%$، $n=60 \Rightarrow 4.9\%$). لذلك لا يُدّعى إغلاق بوابة القبول النهائية من عينة صغيرة حتى لو كانت نتيجتها الظاهرية 100%.
