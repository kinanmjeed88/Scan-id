# محرك OCR الإنتاجي — PP-OCRv5 على ONNX Runtime (ADR-010)

**الحالة (2026-11-04): محرك OCR حقيقي يعمل داخل التطبيق ومشحون معه، بلا شبكة.
لم تُقس دقته الميدانية على مستمسكات عراقية حقيقية بعد — انظر «ما أُثبت وما لم
يُثبت» في آخر الوثيقة قبل أي ادعاء.**

> هذه الوثيقة تحل محل العبارة السابقة «لا يُشحن محرك OCR» في
> [`OCR_EVALUATION.md`](OCR_EVALUATION.md)، مع بقاء تقييم البدائل وسبب رفض
> ML Kit وTesseract وWindows.Media.Ocr كما هو مسجَّلاً هناك.

## 1. الاختيار

| العنصر | القيمة |
|---|---|
| كشف الأسطر | PP-OCRv5 mobile detection (DBNet)، ONNX |
| التعرف على النص | PP-OCRv5 mobile Arabic recognition (CTC)، ONNX |
| المصدر | `PaddlePaddle/PP-OCRv5_mobile_det_onnx@e6f4fa85…`، `PaddlePaddle/arabic_PP-OCRv5_mobile_rec_onnx@14aaedcd…` |
| الترخيص | Apache-2.0 للملفين (وهو ترخيص PaddleOCR) |
| الحجم | 4,826,518 B + 7,998,947 B ≈ 12.2 MiB، لا شيء غيرها |
| وقت التشغيل | `flutter_onnxruntime` (MIT) الموجود أصلاً للكشف عن الحدود — **لم تُضف اعتمادية جديدة** |
| المنصات | Android (arm64/armv7 المعتادة في المشروع) وWindows x64؛ نفس المحرك ونفس الأوزان |
| الشبكة | لا شيء وقت التشغيل: الأوزان مضمّنة في الحزمة، ولا يوجد تنزيل ولا استدعاء خدمة |
| النص | عربي (٧٤٧ رمزاً في القاموس، مع التشكيل والأرقام العربية-الهندية) + لاتيني + أرقام |

رفض ML Kit نهائياً: لا يدعم العربية ولا يعمل على Windows (تفصيل في
`OCR_EVALUATION.md`). ورفض Tesseract لأسباب التغليف على المنصتين نفسها. ولم
يُعتمد Windows.Media.Ocr لأنه كان سيعني محركين بملفَي دقة مختلفين لنفس المستند.

**لماذا PaddleOCR تحديداً:** النموذج العربي المتعدد اللغات لـPP-OCRv5 متاح
كتصدير ONNX رسمي من نفس الجهة المنتجة للنموذج، بترخيص Apache-2.0، وبحجم يناسب
الهاتف، ويمكن تشغيله بمحرك ONNX Runtime الموجود أصلاً في التطبيق — أي بلا
اعتمادية أصلية جديدة ولا بناء NDK إضافي.

## 2. المسار داخل التطبيق

```
preview bytes (≤1200 px، من معاينة المستند المعزولة)
  → decodeForProcessing(bytes)                     [Isolate]
  → buildOcrDetInput: long-edge 960، 32-aligned، BGR مستوٍ،
    ImageNet mean/std                              [Isolate]
  → OrtPpocrRuntime.runDetection → خريطة احتمال [1,1,H,W]
  → decodeTextBoxes: عتبة 0.3، مكوّنات 8-connectivity،
    أدنى مستطيل دوّار، unclip 1.5، عتبة صندوق 0.6      [Isolate]
  → لكل سطر: buildOcrLineInput: ارتفاع 48، عرض بنسبة
    السطر (٨-aligned، حتى 960)، BGR، v/127.5−1        [Isolate]
  → OrtPpocrRuntime.runRecognition → [1,T,C]
  → probabilitiesFromLogits عند الحاجة → decodeCtcLine
  → OcrTextResult(lines: النص + الثقة + الحدود المعيارية)
```

نقاط الاتصال بالكود:

| الطبقة | الملف |
|---|---|
| العقد | `lib/application/ocr_engine.dart` (`OcrEngine`) |
| المحرك | `lib/application/paddle_ocr_engine.dart` (`PaddleOcrEngine`) |
| ربط ONNX | `lib/application/paddle_ocr_runtime.dart` (`OrtPpocrRuntime`) |
| مواصفات الملفات | `lib/application/ocr_model_assets.dart` |
| معالجة الصورة | `lib/imaging/ocr_tensor.dart` |
| فك صناديق DB | `lib/imaging/db_text_boxes.dart` |
| فك CTC والقاموس | `lib/domain/ocr_decoding.dart` |
| إدخال المحرك في التطبيق | `lib/main.dart` → `createPlatformOcrEngine()` |
| جلب الأوزان في البناء | `tool/fetch_ocr_models.py` |

## 3. الضوابط

- **عمل محدود**: ٣٢ سطراً كحد أقصى و٢٥ ثانية لكل مستند. عند استنفاد الزمن
  تُعاد الأسطر التي اكتملت، وإن لم يكتمل شيء فالنتيجة `unavailable` بسبب
  `time-budget-exceeded` — لا نجاح كاذب.
- **لا تلفيق**: نص فارغ يبقى فارغاً، والثقة غائبة (`null`) عند غياب النص،
  والأسطر التي تقل ثقتها عن 0.3 تُهمل بدل تخمينها. صنف خارج القاموس يُهمل ولا
  يُخمَّن له حرف.
- **الإلغاء**: `OperationCancelled` هو الاستثناء الوحيد الذي يخرج من المحرك؛
  كل فشل آخر يصبح `OcrTextResult.unavailable` برمز آمن
  (`model-unavailable`، `engine-failure`، `time-budget-exceeded`).
- **الخصوصية**: صورة المستند لا تترك الجهاز، والنص المُتعرَّف عليه يعيش داخل
  تشغيل واحد فقط؛ المسار يستخرج منه درجة أدلة كلمات مفتاحية ثم يُهمله. لا
  يُسجَّل النص ولا يُحفظ في المشروع ولا في النسخ الاحتياطية.
- **عدم تجميد الواجهة**: فك الصورة وبناء المصفوفات وفك الصناديق تعمل في
  `Isolate.run`، واستدعاءات ONNX غير متزامنة أصلاً.
- **بلا شبكة**: `AndroidManifest` لم يُمسّ (لا صلاحية كاميرا/إنترنت جديدة)،
  والملفان يُقرآن من `rootBundle` كأصول مضمّنة.

## 4. هوية الأوزان وتكرار البناء

`tool/fetch_ocr_models.py` ينزّل الملفين من مراجعة مُثبَّتة في مستودع
PaddlePaddle على Hugging Face، ويتحقق من **الحجم وSHA-256** قبل استخدام البايتات،
ويكتب إلى ملف مؤقت ثم `replace` ذري، ويرفض الكتابة فوق ملف موجود لا يطابق
البصمة. الأوزان مستثناة من Git (`.gitignore`) مثل وزن DocAligner، ويُستعادان في
CI بمفتاح هو البصمة نفسها.

القاموس (`assets/ocr/ppocrv5_arabic_dict.txt`, 747 سطراً، بصمة
`7f92f7db…`) **مُلتزَم في المستودع** لأنه نص صغير قابل للمراجعة، و`-text` في
`.gitattributes` يحفظ بايتاته كما هي على Windows وLinux. بواباة
`tool/check_detector_retirement.py` ترفض أي `.onnx` غير مُدرَج ببصمته في قائمة
مراجعة، وترفض قاموساً تغيّرت بصمته أو عدد رموزه.

## 6. ما أُثبت وما لم يُثبت

**أُثبت:**

- الأوزان تُنزَّل بتطابق البصمة وتُحمَّل في ONNX Runtime وتُنتج مخرجات بالأشكال
  المتوقعة (اختبار Windows أعلاه).
- المسار الكامل من بايتات صورة إلى `OcrTextResult` يعمل على Windows وينتج نصاً
  لاتينياً وأرقاماً صحيحة على صفحة مرسومة.
- النموذج العربي يُنتج حروفاً عربية (لا نصًّا لاتينياً عشوائياً) على صفحة عربية
  مرسومة.
- الوحدات الحتمية (DB، CTC، المصفوفات، القاموس) مغطاة باختبارات وحدات.

**لم يُثبت، ولا يجوز ادعاؤه:**

- **دقة قراءة عربية على مستمسكات عراقية حقيقية**: لا توجد مجموعة صور حقيقية
  مسموح بها مع نصوص مرجعية مستقلة في هذا المستودع. صفحة مرسومة بخط النظام ليست
  صورة بطاقة: لا انعكاس، لا ظل، لا ضغط، لا طباعة أمنية.
- **CER/WER فعلي**: لم يُقس على أي مجموعة. الأدوات موجودة
  (`lib/domain/ocr_metrics.dart`) لكن لا بيانات مرجعية.
- **زمن المعالجة والذاكرة على هاتف حقيقي**: لم يُقس. الأرقام غير معلنة.
- **دقة التصنيف الأربعة أنواع**: تعتمد على معجم المراسي، ولم تُقس.

## 7. كيف تُقاس الدقة عندما تتوفر بيانات مسموح بها

1. اجمع صوراً مسموحاً باستخدامها (بموافقة المالك) مع نص مرجعي مدقَّق يدوياً لكل
   صورة، وأخفِ ما لا يلزم من معلومات شخصية.
2. افصل تدريب/ضبط/اختباراً، وامنع تكرار المستند نفسه أو نسخه بين المجموعات.
3. شغّل المحرك على صور المجموعة (على جهاز أو في اختبار تكامل)، واحسب
   `characterErrorRate`/`wordErrorRate` من `lib/domain/ocr_metrics.dart`.
4. احسب لكل نوع Precision/Recall/F1 ومصفوفة الالتباس بـ
   `ClassificationReport`، وأبلغ عن نسبة `unknown` وطلبات المراجعة.
5. سجّل النتائج في [`OCR_EVALUATION.md`](OCR_EVALUATION.md) مع حدود المجموعة.

حتى ذلك الحين، أي رقم دقة يُذكر عن هذا المحرك هو ادعاء غير مدعوم.
