# تقرير معمارية وتدقيق: التعرّف الذكي على الدفعات + الترتيب التلقائي

**التاريخ:** 2026-10-07 · **الفرع:** `arena/bc17c7f3-scan-id` (PR #4)

> **الحالة: تقرير تصميم فقط.** لا يوجد في المستودع أي OCR أو نموذج تعلّم آلي أو «ذكاء اصطناعي»، ولم يُضف شيء منها في هذا الـ PR. كل ما يلي وصف للشيفرة الحالية (مع مراجع ملفاتها) واقتراح لطبقة إضافية لم تُنفَّذ.

## 1. الهدف والقيود

- **التعرّف الذكي على الدفعات:** إدخال مجموعة صور؛ لكل صورة: العثور على المستمسك أو المستمسكات، قصّها، تحديد نوعها، والإبلاغ عن الثقة.
- **الترتيب التلقائي:** وضع الناتج على A4 بالمقاس الحقيقي وبالترتيب المطلوب.
- **قيد ملزم:** الطبقة الجديدة إضافية فوق الأنظمة الموجودة: المحرر، المليمتر، A4، `arrangeDocuments`. **لا نظام إحداثيات ثانٍ ولا نظام A4 ثانٍ.** كل ناتج يمر عبر `DocumentItem` (مم) و`DocumentSizeCatalog` و`arrangeDocuments`.

## 2. خط المعالجة الحالي (كما هو في الشيفرة)

```
ProjectService.importImages            ← نسخ الأصل + نسخة عمل + مصغرة (isolate)
  └─ ProjectService.arrangeImportedImages(project, assetIds, keepPlaced)
       لكل صورة بالتتابع:
         ImageEditor.open → EditorSource(preview ≤1200px)
         ImageEditor.suggest(preview) → suggestDocumentCorners (isolate) → 4 زوايا | null
         CropDraft.toRecipe → أبعاد الناتج
         suggestDocumentType(name, w, h, catalog) → DocumentTypeSuggestion(kind, confidence, reason)
         catalog.sizeFor(kind) → قص ثانٍ بنسبة المقاس الرسمي → applyCrop (نسخة محفوظة)
         DocumentItem(pageIndex: null, documentKind, recognitionConfidence, sizeConfirmed)
       arrangeDocuments(project, keepPlaced) → projects.save (حفظ واحد للعناصر)
  └─ LayoutEditorController: مراجعة/تصحيح (قائمة النوع، شريط «خارج الورق»، تراجع)
```

## 3. نقاط الربط الموجودة (يُبنى عليها دون استبدال)

| نقطة الربط | الملف | لماذا تصلح |
|---|---|---|
| `ImageEditor.suggest(Uint8List) → List<Point2>?` | `lib/application/contracts.dart` | واجهة؛ يمكن أن يقف خلفها كاشف أفضل دون لمس الخدمة أو الواجهة |
| `DocumentTypeSuggestion { kind, confidence, reason }` | `lib/domain/document_kind.dart` | شكل ناتج مصنِّف جاهز، والثقة محفوظة في `DocumentItem.recognitionConfidence` |
| `DocumentSizeCatalog` | `lib/domain/document_kind.dart` | مصدر المقاس الوحيد؛ المصنِّف يحدد النوع فقط |
| `arrangeDocuments(keepPlaced: true)` | `lib/domain/arrangement.dart` | يضيف دفعة جديدة حول ما رتبه المستخدم دون تحريكه |
| `awaitingSize` / `unplaced` | `ArrangementResult` | مسار «يحتاج مراجعة» و«لا يتسع» موجود |
| `ExportPlan.warnings` (ثقة < 0.85) | `lib/domain/export_plan.dart` | تنبيه قبل الطباعة موجود |

## 5. معمارية مقترحة (إضافية، غير منفذة)

1. **واجهة `DocumentRecognizer`** في `application/contracts.dart`:
   `Future<List<RecognizedDocument>> recognize(EditorSource source, DocumentSizeCatalog catalog)`
   حيث `RecognizedDocument { corners, kind, confidence, reason, source }`.
   **التنفيذ الافتراضي** يغلّف ما هو موجود حرفياً (`suggestDocumentCorners` + `suggestDocumentType`)، فيكون أول تغيير بلا أي تغيير سلوك ويُثبت ذلك بالاختبارات الحالية. أي نموذج لاحق تنفيذ آخر خلف الواجهة نفسها.
2. **`BatchRecognitionService`** في `application/`: يمر على الصور مع تقدّم وإلغاء، وينتج **خطة نقية** (`RecognitionPlan`) بلا كتابة. ثم يطبّق الخطة دفعة واحدة عبر `applyCrop` الحالي و`DocumentItem` و`arrangeDocuments(keepPlaced: true)`، كأمر واحد في سجل التراجع.
3. **بوابة الثقة (F3):** ثقة ≥ عتبة ← يوضع؛ دون العتبة ← يبقى خارج الورق مع النوع المقترح ليؤكده المستخدم بنقرة. هذا **تغيير سلوك** عن الحالي ويحتاج موافقة.
4. **حفظ المصدر والسبب (F6):** حقلان اختياريان في `DocumentItem` (schema 5 مع قراءة 1–4).
5. **عدة مستمسكات لكل صورة (F1/F2):** بعد قرار F2. الخيار الأقل خطراً صور مشتقة تشترك في الأصل الثابت، لأن التصدير والتخزين والنسخ الاحتياطي تفترض أن القص على الصورة.
6. **ما لا يتغير:** المليمتر، `PageCanvas` كمحوِّل وحيد إلى بكسلات، `arrangeDocuments` كمرتِّب وحيد، الكتالوج كمصدر وحيد للمقاس، و«مقاس غير مؤكد لا يوضع على الورق».
