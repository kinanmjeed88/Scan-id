# ADR-001 — Sembast remains the persistence layer

- **Status:** Accepted
- **Date:** 2026-10-08
- **Baseline:** `14a3ee7b46ad6b1c0a5bdb912765e232dfb3ec33`

## Context
An external specification repeatedly referenced "Isar collections" and
"generated model extensions". The actual Scan-id persistence layer is
**sembast** (`sembast 3.7.2`), a pure-Dart document store, used by
`lib/persistence/local_project_repository.dart` (store `projects`, optimistic
`revision`, `RecoveryCheckpoints`, explicit `recover`). There are **zero** Isar
imports and no code generation in the project.

## Decision
Keep **sembast** as the persistence layer. Do **not** introduce Isar merely
because an external specification mentioned Isar or generated models.

## Consequences
- All persistence requirements from the specification are re-mapped onto the
  sembast project record (JSON with `schemaVersion`).
- "Schema" in Scan-id means the on-disk `schemaVersion` of the project JSON,
  not Isar collection versions.
- No code generation step; no new dependency; `flutter analyze` stays clean
  without generated-file import auditing for a DB layer.
- Schema evolution is expressed in `lib/domain/project.dart` (`Project.fromJson`
  / `toJson`) plus an explicit, tested migration step (see ADR-010, ADR-011).

## Alternatives considered
- **Introduce Isar** — rejected: new native/FFI dependency + build_runner code
  generation + generated-extension import surface, for no functional gain over
  sembast; violates the reuse-before-create rule and the "stop before adding a
  dependency" rule (owner approval would be required).
