# ADR-003 — Source images are immutable; derived assets are separate

- **Status:** Accepted
- **Date:** 2026-10-08

## Context
`ImageAsset` already models an immutable original plus derived files:
`originalPath` (byte-identical copy, EXIF preserved), `workingPath` (EXIF-baked
PNG), `thumbnailPath` (JPEG). `LocalAssetRepository` writes originals once and
never overwrites; replacements live under `replacements/<id>`; crop edits live
under `edits/<id>` (`LocalImageEditor.createRevision`).

## Decision
The **original source image is immutable**. Every derived result (perspective
correction, orientation, OCR input, classification input) is a **separate**
`ProcessedDocumentAsset` that is always regenerable from the source and never
mutates it.

## Consequences
- Multi-document recognition produces one derived asset per detected document,
  all tracing back to the same immutable source.
- No destructive sanitization of originals (EXIF retained by design).
- Provenance must record source → detection → processed asset (see ADR-008).
- Failure of any derived stage keeps the source intact and falls back to manual
  workflow.

## Alternatives considered
- In-place crop of the working image only (current single-document behavior) —
  retained for the manual path, but insufficient for multi-document; the
  recognition path uses explicit derived assets.
