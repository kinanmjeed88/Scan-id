# ADR-004 — Recognition state is separated from user overrides

- **Status:** Accepted
- **Date:** 2026-10-08

## Context
Today `DocumentEdits.setKind` (`lib/domain/document_edits.dart`) applies a
user-chosen category and sets `recognitionConfidence: 0`. That conflates "the
user decided" with "the AI had no confidence" and destroys the AI metadata. The
specification requires that user decisions are authoritative and stored
**separately** from AI results, and that the AI never overwrites an override.

## Decision
Introduce a **separate `UserOverride` layer** and keep AI results
(`RecognitionResult`) intact. Effective value = override if present, otherwise
the AI result. A user override must **not** destroy AI metadata by zeroing
confidence; it must be recorded as an explicit override with its own
provenance.

## Consequences
- `DocumentItem` (or a parallel recognition record) gains an override layer for
  type, preset variant, corners, side, pairing, inclusion, size, rotation, page
  and position.
- Re-run reconciliation updates only non-overridden AI fields and flags
  "recognition changed"; overrides always survive (see ADR-008 chain and the
  reconciliation contract in `docs/AUDIT.md`).
- The current `recognitionConfidence: 0` behavior in `setKind` is an explicit
  anti-pattern to be corrected in Phase 4; it is **not** the model going forward.

## Alternatives considered
- Keep zeroing confidence as the "override" signal — rejected: loses evidence,
  breaks "explain why it was classified this way", and cannot distinguish
  "user overrode a high-confidence result" from "model was unsure".
