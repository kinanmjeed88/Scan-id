# ADR-005 — Offline-first recognition

- **Status:** Accepted
- **Date:** 2026-10-08

## Context
Scan-id is an offline workspace. The release Android manifest declares **no
INTERNET permission** (`android/app/src/main/AndroidManifest.xml`; only
`debug`/`profile` add it per the Flutter template), `allowBackup=false`, and
data-extraction rules are set. `lib/` imports no networking package
(`package:http`, `HttpClient`, `dio` are absent); `dart:io` is used only for
file IO.

## Decision
Recognition is fully offline. **No** cloud document upload, **no** remote OCR,
**no** runtime model download. Models are bundled with the app, listed in a
manifest with hashes and licenses, and never fetched at runtime.

## Consequences
- A CI **import guard** must fail the build if recognition code imports a
  networking library.
- Model candidates must run on-device on Android and Windows, CPU-capable, with
  offline packaging (see the OCR/Model Evaluation Plan in `docs/AUDIT.md`).
- Privacy invariants (no INTERNET, no telemetry of document contents) are
  unchanged and re-audited each phase.

## Alternatives considered
- Cloud OCR/inference — rejected: violates the offline mission and privacy
  requirements; would require adding INTERNET, which is prohibited.

## Amendment — 2026-10-16: the one socket this app is allowed to open

The context above said the release manifest declares **no INTERNET**, and that
`dart:io` is used only for file IO. Both were true when written, and both were
the reason the in-app update check could never work on a user's phone: the
Android release build cannot open a socket without `INTERNET`, so every check
failed in the kernel before the code saw an answer — while the screen told the
person to check their connection.

This decision is not reversed. **Recognition, correction, storage, backup and
export remain fully offline, and no document data may ever reach the network.**
What is added is one narrow, user-initiated exception, so that the app can
finish the job it already promised to do.

### What is now permitted

- The `INTERNET` and `REQUEST_INSTALL_PACKAGES` permissions in the release
  manifest — that exact pair, asserted by `tool/check_source.py`, so a widened
  grant fails the gate the same way a missing one would.
- Reading published release metadata over HTTPS from the fixed hosts listed in
  `_trustedUpdateHosts` (`lib/application/ota_update.dart`), redirects refused,
  size bounded, with a connect/read timeout so a captive portal cannot hang the
  settings screen.
- Downloading the release asset into `cache/scan-updates` (the app's own
  directory), verifying it against the published SHA-256, and handing it to the
  system package installer through a `FileProvider` that declares one path.
- Sending the installed version number to the release feed — the only value
  that leaves the device, and only while a check is running.

### What stays forbidden

Uploading images, project data, names, or telemetry; fetching a model at
runtime; cloud OCR or inference; an installer path on a platform where the
package is not signed and verified first (`UpdateService.installUpdate` refuses
instead of guessing). A build with no installer configured says so, in words the
tests assert.

### Consequences

- `docs/ARCHITECTURE.md` (S8) and `docs/AUDIT.md` describe the lifecycle and the
  permission gate; the CI privacy gate reads "exactly these two permissions"
  rather than "no INTERNET".
- The privacy sentence users can see, in the update card itself, states that
  networking is used for this check and this download only.
