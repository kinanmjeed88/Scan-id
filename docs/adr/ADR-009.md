# ADR-009 — Worker abstraction for long-running recognition

- **Status:** Accepted
- **Date:** 2026-10-08

## Context
Heavy work already runs off the UI isolate via one-shot `Isolate.run`
(import, detect, warp, export, auto-adjust). One-shot isolates cannot express
bounded concurrency, streaming progress, cooperative cancellation, or reuse of
model sessions across documents.

## Decision
Long-running recognition uses a **worker abstraction** with:
- **bounded concurrency** (one image at a time on Android, up to two on Windows,
  initial values, tuned by benchmark evidence);
- **progress** events per stage and per document;
- **cooperative cancellation** checked at stage boundaries and between documents
  (native/FFI calls that cannot be interrupted have their results discarded and
  buffers released on return);
- **deterministic resource release** (model sessions created once per worker and
  reused; released on lifecycle events or teardown);
- **failure isolation** (one failed document never affects others; one failed
  image never affects the batch).

Arbitrary sleeps, timing hacks and oversized `pumpAndSettle` timeouts are
prohibited; tests wait on real transitions via streams, completers or test
hooks.

## Consequences
- A long-lived worker isolate owns model sessions and native handles; the UI
  exchanges typed messages.
- Large pixel buffers cross isolate boundaries by transfer or file hand-off, not
  repeated copying.
- Cancellation is proven by test hooks, not by timing.

## Alternatives considered
- Keep `Isolate.run` per operation — rejected: no cancellation, no session
  reuse, no bounded queue, and re-decoding per call.
