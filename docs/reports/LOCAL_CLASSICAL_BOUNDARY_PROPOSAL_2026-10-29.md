# التنفيذ المحلي لاقتراح حدود هندسي — 2026-10-29

## القرار والنطاق

لم يثبت أي وزن متخصص يجتاز سلسلة حقوق البيانات/التوزيع ودمج runtime الحقيقي على Android وWindows. لذلك لم يُدمج DocQuadNet أو DocAligner أو LDED، ولم يُعاد `ScanIdDocNet-v1`. هذا التغيير لا يدعي وجود كشف AI أو قياس دقة واقعية. فعّل الكاشف الهندسي المحلي الموجود مسبقاً كـ **مصدر اقتراح رباعي لمستند واحد**، مع إبقاء التحقق الصارم ومراجعة المستخدم قبل القص. لا كشف متعدد المستندات.

## المسار الفعلي بعد التغيير

1. `LocalImageEditor.open` يقرأ نسخة المعالجة بعد تطبيق EXIF المخزنة، ويبقي الأصل للقراءة فقط، وينشئ preview محدوداً.
2. `LocalImageEditor.suggestProposal` يشغل `detectDocumentCornersScored` على preview داخل isolate قابل للإلغاء. تعاد النقاط مطبعة ضمن فضاء preview المتوافق مع الصورة الموجهة كاملة.
3. النتيجة تُسجل `BoundaryProducer.detector` دون تحويل نتيجة score إلى احتمال/ثقة.
4. `verifyBoundary` يعيد تطبيق تقييم الرباعي الموجود. منتج detector يحمل سبب مراجعة `uncalibratedClassicalScore`؛ لذلك لا يجيز قصاً تلقائياً اعتماداً على score غير معاير.
5. الاقتراح الهندسي الصالح هندسياً يحفظ في `ImageAsset.suggestedCrop` فقط؛ لا يتغير `crop` المعتمد ولا `polygon` البشري. واجهة القص الموجودة تعرض الاقتراح للتعديل اليدوي. عند اعتماد المستخدم، القص/المنظور يستخدمان خط المعالجة القائم من الأصل، ثم المعاينة والحفظ القائمين.
6. لا نتيجة صالحة أو إلغاء أو خطأ: لا اقتراح قديم يعتمد؛ تبقى الصورة الأصلية كاملة ويستطيع المستخدم تحديد الزوايا يدوياً.

- **DocAligner 1.1.1:** التقرير السابق يسجل موافقة Apache-2.0 على الأوزان، لكن حقوق مجموعة التدريب ومصادر الطرف الثالث غير مكتملة، ولم يثبت تشغيل تطبيق Android/Windows محلياً في هذا المستودع.
- **LDED:** المقال يربط المستودع الأصلي [ateso-group/lded_edge_detection](https://github.com/ateso-group/lded_edge_detection)، HEAD الذي فُحص `07883a4e9994fb965abd3b1597eb336ed1f04ad7`. GitHub API يعرض `license=null`، ولا توجد Releases، ولا ملف نموذج/وزن ضمن شجرة المستودع؛ مجلد `lded/models/checkpoints` يحتوي صوراً ومخطط مقاييس فقط. المقال يصف الأوزان والنتائج والتدريب لكنه ليس ترخيصاً ولا ملف وزن قابلاً لإعادة التنزيل. تقييم الأرقام المنشورة على مجموعة validation خاصة بالمطور، وليس اختباراً مستقلاً أو عراقياً. النتيجة: متخصص واعد بحثياً لكنه غير مؤهل للتوزيع/الدمج؛ لم تُخمن رخصة أو بصمة.
- **البدائل:** لم يظهر بديل يجمع تخصص الزوايا، حقوق الأوزان والبيانات، ملفاً كاملاً قابلاً للتوزيع، ونجاح runtime على المنصتين. ترخيص الكود وحده لا يكفي.

هذه قرارات أهلية دمج، وليست إثباتاً أن الطرق لا تعمل بحثياً. لا أرقام دقة منشورة تُنقل كقياس للتطبيق.
