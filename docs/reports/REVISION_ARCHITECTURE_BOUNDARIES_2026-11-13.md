## الأدلة على حدود Sembast والقفل

وثائق Sembast المثبتة `3.7.2` تنص صراحةً على أن [IO غير آمن بين isolates أو العمليات](https://github.com/tekartik/sembast.dart/blob/v3.7.2/sembast/doc/how_to.md#isolates)، وقد تحدث خسارة أو تلف، وتصف [التنفيذ بأنه single-process/single-isolate](https://github.com/tekartik/sembast.dart/blob/v3.7.2/sembast/doc/implementation_details.md#io-file). مصدر المصنع يحتفظ بخريطة helpers داخل instance لا عبر العمليات؛ معاملات السجل لا تشمل filesystem. لا يثبت ذلك سلوك كل حالة غير مدعومة، ولا يثبت أن مسار إنتاج حالياً يفتح DB في عامل.

توثيق Dart `RandomAccessFile.lock` للإصدار المثبّت يحذر من الفروق بين المنصات ومن أن قفل Linux/macOS على مستوى العملية؛ يسمح لعدة isolates بالحصول عليه، وقد يؤثر إغلاق descriptor آخر. على Windows يرتبط القفل بالـhandle. لذلك لا يُقبل قفل Dart منفرد بوصفه ضماناً موحداً دون طبقة تمنع تعدد المالكين داخل العملية واختبارات فعلية على المنصتين. إنشاء lockfile حصرياً وحده يترك سؤال crash وملف stale؛ لا يصح حذفه اعتماداً على عمر أو PID وحده.

`test/integration/sembast_isolate_diagnostic_test.dart` يحجز التسلسل دون تأخير: يفتح المالك قاعدة فارغة، ويفتح isolate ثانٍ نفس الجذر وينشئ سجلاً، ثم يفحص قائمة المالك ويغلق ويعيد الفتح. هدفه تشخيص النسخة القديمة على بيئة الاختبار فقط، وليس إثبات سلامة أو عمومية السلوك غير المدعوم. لا يحاكي عملية مستقلة أو Android/Windows.

## مرشح التصميم وحدوده — NOT VERIFIED

المرشح هو مالك واحد للجذر ومدير lifecycle في isolate الرئيسي، مع استبعاد على مستوى نظام التشغيل طوال عمر فتح Sembast **وقبل** قراءة المؤشر أو تعديل checkpoints. العمال ينفذون تجهيز الملفات بأسماء محجوزة ويسلمون النتائج للمالك فقط، ولا يفتحون DB أو يحذفون خارج تعليمات المالك. فتح ثانٍ داخل العملية أو من عملية أخرى يُرفض أو يمر عبر قناة المالك؛ لا يُسمح بنسخة Sembast مستقلة. الاختيار بين واجهات native أو بديل مكافئ لم يُحسم لأن دلالات Android وWindows والإقفال بعد crash والاختبارات لم تثبت بعد. لا يعتبر مجرد تسمية actor أو mutex تنفيذاً.

| الحالة | التحول المقترح والشرط | انقطاع أو فشل |
|---|---|---|
| `reserved/staging` | ينشئ المالك نية منتج ذات هوية ووجهة قبل إرسال العمل؛ يشمل الاستعادة والاستيراد وإعادة البناء وناتج محرر يعود للمستدعي. staging والوجهة محميان منذ الحجز وحتى نهاية العامل والقرار. | سجل غير مقروء أو ملكية ملتبسة => احتفاظ ورفض الصيانة، لا مهلة عمر. لا تفترض الإلغاء أن العامل توقف. |
| `published` | العامل يُكمل ملفاته في مسار محجوز، والمالك فقط يوافق على نشرها دون استبدال ملفات موجودة. لا تفقد الاستعادة الحجز بين rename و`create`. | بعد الانهيار يُبقي الاسترداد الوجهة إن لم يستطع إثبات حالتها؛ لا تُعدّ البيانات غير المعروفة يتيمة. |
| `committed` | تحت نفس تسلسل الحذف، يتحقق المالك من جميع ملفات الحالة الجديدة (الحالية، كل التاريخ، الوثائق والمشترك) ثم يحفظ metadata، ويحدّث checkpoints وفق سياسة الفشل الموجودة. بعد commit لا يبلغ فشلاً كأن الحفظ لم يحدث. | إن فشل checkpoint تبقى المراجع القديمة والجديدة محمية إلى الإصلاح؛ لا يخترع علاقات. |
| `pending deletion` | تُسجل نية متينة محددة الهدف بعد قرار حذف منطقي أو طلب GC، مع حظر الخلط بين هويات الأصول والمراجعات. `findOrphans` اقتراح وليس تفويضاً نهائياً. | فشل إنشاء/قراءة النية => لا unlink؛ تعارض هدف أو ملف مجهول => احتفاظ وإبلاغ. |
| `recheck/delete` | تحت تسلسل المالك، يعاد التحقق من السجلات الحية، نقاط الاسترداد، snapshots، الحجوزات، والقراء وundo المؤهل. عند ظهور مرجع تُلغى النية؛ وإلا فقط يُسمح بالحذف. لا يُسمح لـcommit مرجع من ملف بعد أن فاز حذفه؛ يفشل التحقق بوضوح. | `unlink` جزئي أو crash بين DB وfilesystem يتطلب حالات مسجلة قابلة لإعادة المحاولة؛ لا يدّعى أن Sembast وfilesystem معاملة واحدة. يجب إثبات ترتيب الاستمرارية الحقيقي على Android وWindows، وألا يحذف restart ملفاً قد صار مستخدماً. |
| `recovery` | عند بدء المالك الجديد يتوقف النشر والتنظيف حتى تُقرأ الحالات، وتُحسم أو تُحتفظ بالملفات وتُبلّغ التعارضات. تُعامل قاعدة `recover` والمؤشر كجزء من المجال نفسه. | لا تُحذف لقطات الترحيل أو المراجع غير المقروءة، ولا يُنشأ أب غير مثبت. |

تفاصيل journal، ذرية rename، استعادة ملف نقل جزئياً، تعارض الوجهة، وتحرير حجوزات نتائج التحرير المهجورة ما زالت أسئلة تنفيذية غير مثبتة. يجب اختيار سلوك متوافق لكل منصة واختباره قبل الاعتماد؛ سياسة تعطيل الحذف دائماً ليست بديلاً مقبولاً. تظل أدوات خارج التطبيق أو إصدارات لا تشارك البروتوكول خارج الضمان.
