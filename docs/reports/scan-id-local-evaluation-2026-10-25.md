# التقييم المحلي غير الموسوم — Scan-id

**التاريخ:** 2026-10-25
**البيانات:** عينة `Mostmskat/` المحلية، دون نقل إلى خدمة أو CI
**الغرض:** فحص سلوك خط الحدود بعد الإصلاح، لا تقدير الدقة ولا اعتماد نموذج/OCR.

## حدود الخصوصية والنطاق

- عُثر محلياً على **19 صورة ثابتة قابلة لفك JPEG**. لم تُقرأ ملفات الفيديو أو نسخة `.scanid` الاحتياطية. لم يُحفظ أو يُطبع أي اسم ملف أو نص OCR أو إحداثيات أو تنبؤ لكل صورة.
- قرأ المشغّل الصور في الذاكرة فقط بعد تطبيق EXIF orientation؛ حفظ ملخصاً عددياً عاماً تحت `local-data/`، وهو مسار مستثنى من Git. لم يحفظ بكسلات أو OCR أو سجلات لكل صورة، ولم يستدعِ أي خدمة خارجية.
- أُضيف استثناء sparse partial checkout لكل استدعاءات `actions/checkout` في workflows، مع فحص ساكن في CI وفحص وجودي داخل workflow الرئيسي؛ الصور تبقى خارج worktree وملفات CI.
- التقرير لا يعيد نشر مادة خاصة. التعداد الإجمالي أعلاه هو كل ما يُسجل عن العينة.

## طريقة الإعادة

من جذر المستودع، ببيئة Python محلية فيها `numpy`, `Pillow`, `onnxruntime`, و`onnx`:

```bash
python tool/evaluate_local_mostmskat.py
```

الملخص المحلي الافتراضي: `local-data/mostmskat-local-evaluation-summary.json` (غير متتبع). يقارن المشغّل مسارين على المعاينة نفسها: `frozen_ai_hybrid` و`classical_only`. الحد الأقصى للمعاينة 1200px؛ التحجيم هو Pillow BOX بوصفه تقريباً لتحجيم `package:image`، لذلك هذه **مرآة Python وليست مطابقة مثبتة لـDart**. اسم كل ملف يُستبدل بعلامة محايدة كي لا يدخل دليل الاسم في القياس. تتحقق الأداة أولاً من سلامة الأوزان والعتبات المجمدة.

### التفسير المسموح

المسار الهجين أحال عدداً أكبر بكثير من القرارات إلى المراجعة مقارنة بالمسار الكلاسيكي في هذه العينة غير الموسومة. **لا نعرف من هذه الأرقام أي المسارين أصح:** قبول البوابة ليس حكماً بشرياً، ولا يوجد عدد مستندات مرجعي أو حدود مستقلة لكل صورة. قد تعني الفجوة مراجعة زائدة، أو حماية لازمة من قص خاطئ، أو اختلافاً في المرشحين؛ هذه الاحتمالات لا يمكن فصلها دون وسم مستقل.

تؤكد النتائج أيضاً سبب فصل «الهندسة المقبولة» عن «إذن القص»: وجود 18 صورة ذات هندسة مقبولة في كلا المسارين لا يساوي 18 قصاً صحيحاً. لا أستنتج precision أو recall أو تحسناً أو تراجعاً في الدقة، ولا أستخدمها لمعايرة أي عتبة.

## ما لم يُقيّم

- لا توجد labels مستقلة لعدد الوثائق أو الزوايا أو القص المقبول؛ لذلك لا توجد دقة أو IoU أو false-positive/false-negative صالحة للإعلان.
- لم تُقرأ نصوص عربية أو لاتينية أو أرقام؛ التطبيق لا يضم محرك OCR، ولا توجد CER/WER.
- لا يمثل القياس استدلال Dart، ولا Flutter Analyze/Test، ولا Android/Windows build، ولا أداء جهاز فعلي. SDK غير متوفر في بيئة العمل.
- لم يُجرَ تدريب أو تكييف أو تصدير أوزان جديدة. الأوزان الأصلية والعتبات العصبية الـ14 وعتبات التوجيه الـ5 بقيت كما هي.

## الخطوة التالية للقياس

إذا توفرت موافقة ووسوم بشرية مستقلة، استخدم مجموعة تطوير ومجموعة اختبار مفصولتين حسب جلسة الالتقاط، وأخفِ بيانات النص الشخصي. احسب الاسترجاع لكل وثيقة، split/merge، خطأ الزوايا/الحواف، precision للقص التلقائي ومعدل المراجعة، واعرض الثقة الإحصائية. أبقِ الصور محلياً؛ لا ترفعها إلى Git أو CI أو خدمة خارجية. حتى ذلك الوقت يبقى هذا التقرير **screen تشغيلياً غير موسوم فقط**.
